## Industry Thinking

Judgments formed through practice in e-commerce and AI application layer. Updated as practice evolves.

### 1. Token Economics — Not all tokens are worth the same

The depth of Token embedding in the value chain determines its value. Triggering a chat response vs. triggering a transaction costs roughly the same in tokens, but the value differs by orders of magnitude.

Four levels: trigger conversation → trigger recommendation → trigger decision → trigger transaction. The model determines Token cost; the product determines Token value.

### 2. Seat-based → Outcome-based Business Models

AI fundamentally transforms knowledge work at an exponential scale. When AI can independently deliver legal consulting, analysis reports, or video content, the SaaS model of selling tool seats no longer holds. Harvey sells legal consulting, not tool seats. Keling/Jimeng sell content directly. The payment target shifts from tools to outcomes.

### 3. Application Layer Moats

Model providers are entering the application layer directly (Cowork wiped ~$2 trillion SaaS market cap in one week; Claude Code creates strong competition in programming). Five moats that can withstand this, from weak to strong:

1. Distribution & customer relationships (ByteDance, WeChat, DingTalk)
2. Closed-loop data (Harvey, Abridge, Sierra)
3. Industry liability (Sierra, Stripe, Replit) — requires legal entity + SLA
4. Vertical regulatory barriers (healthcare, finance, legal)
5. Physical world (1X, Unitree, embodied intelligence)

Common thread: none of these moats are technology itself — they're trust, relationships, liability, regulation, and physical assets.

### 4. Agent = Model + Harness

Harness engineering (memory, tool use, MCP, multi-agent) is how model capability enters the application layer. Three product design principles from practice:

- **Reduce pause points**: Risk-tiered autonomy (low risk = auto-execute, high risk = ask). Persist user preference patterns. Reverse inquiry — give a draft and let users critique rather than describe needs.
- **Context isolation**: Sandbox each task in independent context. Use existing product structures (Discord channels/threads) as natural boundaries. Use file system as shared memory between human and agent — more transparent than vector databases.
- **Errors don't accumulate**: Roll back decisively, don't patch — LLMs are better at regenerating than local fixes. Multi-agent layering: separate execution from value judgment so errors are caught between layers.

Direction: reduce human intervention frequency while preserving human judgment on critical decisions.
