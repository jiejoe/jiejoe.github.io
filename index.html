02 Practice

探索与实践

基于 OpenClaw 框架，探索 Agent 产品如何进入真实用户场景。

数字分身世界旅行实验

社交 · AIGC
初衷：AI 做梦——如果有平行世界的另一个我在环游世界，会是怎样一种人生。

概念：用自己的面部特征生成一个 AI 数字人，让她代替我在世界各地旅行。每天定时收到她寄来的旅行日记、Live 视频或照片；她拥有自己的小红书主页，经营世界旅行和情感故事内容。

图片/视频生成：实测了 Sora、Seedance、可灵等主流模型，覆盖 Live 图、Vlog、换场景脚本等形式。对比了 1.5 到 2.0 不同版本在人物一致性、场景连贯性和动作自然度上的差异。

内容创作：用 LLM 生成旅行故事剧情和生活化文案，让 AI 尝试了多种故事线——旅行美食打卡、美妙邂逅、旅居悬疑。在内容和图片生成上学习了小红书上旅行博主的排版和内容表达，发布后获得了真人的互动回复。

产品机制：搭建了定时任务系统，按时区自动发布内容；设计了人物情绪状态机，让角色在不同城市表现出不同的性格面。整套流程从脚本生成、素材制作到发布基本跑通了自动化。

个人 AI Harness

生活场景 · 生产力
背景：将生活中所有 AI 增量需求（聊天、P 图、绘画、Coding）完全交给 OpenClaw，连续两个月作为主力工具使用。

做法：按场景拆分频道——Discord（旅行、理财、教育、开发）、飞书（运营、调研、群聊）、微信（通知），前期用 Claude Opus，后自建智能路由（Qwen 3.6 + DeepSeek V4），现回归 Claude Code。

收获：月消耗 600—1000 万 Token，大量 aha moment。但也发现要让更多人在生活中得到好的 AI 服务，Harness 工程在上下文、记忆、协作方面还有大量工作要做。

AI 陪伴硬件

陪伴 · 硬件
初衷：手搓一个 AI 陪伴玩具，作为礼物送给女儿。

做法：基于树莓派制作硬件原型，用 OpenClaw 做长程任务管理和对话调度；同时开发了配套 App，支持语音通话、互动表情、成长记录等功能。

硬件侧：嵌入式 Vibe Coding 成功率不高，硬件编程工具链还不成熟。但可以用 OpenClaw 控制已有能力，如转头、拍照。供应链方面，成熟的低延迟语音硬件方案不多，大多缺少声纹识别，端到端延时仍是核心瓶颈。

语音交互：4 岁以下儿童完全可以与语音助手自然对话，但牙牙学语阶段口齿不清导致 ASR 识别率明显下降。豆包语音也面临同样问题，不过其 iOS SDK 接入流畅，支持自定义 Prompt 和系统级输入，目前正在探索如何将成长记录整合为本地长程记忆，再作为上下文输入给语音模型。

01 商业 · Token Economics

不是所有 Token 都一样值钱。

Token 是 AI 时代的算力单位。但同样一份 Token 的成本，在不同产品里换回的价值天差地别。

让 Token 单价变贵的关键，不在于换什么模型，而在于这份 Token 嵌入了多深的产业链——它能撬动多大的下游决策、是否带着不可复制的上下文、是否替用户完成了真实世界的动作。

一个 Token 触发闲聊回答、触发一次推荐、触发一份合同——成本可能差不多，价值差几个数量级。这是 AI 时代产品经理必须算的商业账。

02 商业 · 计费方式的迁移

席位生意在被结果生意替代。

SaaS 时代的标准生意是按席位卖工具。AI 让另一种生意变得可能：直接卖结果。

这次 AI 革命的本质，不是肌肉劳动的效率变革，而是知识劳动的指数级提升。当一个 AI 可以独立完成一份法律咨询、一篇分析报告、一段视频内容——"卖工具席位"就不再成立。

对个人用户，付费对象从生成工具变成内容本身。对企业用户，Harvey 让"AI 律所"成为可能，直接卖法律咨询，而不是卖工具席位。

03 竞争 · 应用层护城河

应用层的产品如何建立竞争壁垒？

2026 年最大的产业变化，是模型厂直接进入应用层。Cowork 一周内带走了约 $2 万亿 SaaS 市值、Claude Code 在编程领域形成强劲竞争。

这种格局下，应用层还能建立什么竞争壁垒？从弱到强，五种方向：

五种护城河 · 弱 → 强
1
分发与客户关系
字节 · 微信 · 钉钉
用户和销售网络的开拓成本极高，单靠模型能力起不来。
2
闭环数据
Harvey · Abridge · Sierra
用户私域数据加业务流程沉淀的领域数据，通用 API 接触不到。
3
替行业背锅
Sierra · Stripe · Replit
决策出错需要承担专业责任。需要法律实体、保险、SLA 配套。
4
垂直监管壁垒
医疗 · 金融 · 法律
合规、准入、责任认定的硬门槛，纯技术能力突破不了。
5
物理世界
1X · 宇树 · 具身智能
机器人、硬件、供应链——需要长期沉淀的资源。
共同点：都不是技术能力本身，而是信任、关系、责任、监管、物理沉淀。
04 工程 · Model + Harness

Agent = Model + Harness

Anthropic（Claude Code、Cowork）和 OpenAI（Operator、Codex）验证了同一件事——模型进入应用层的方式不是简单包一层 UI，而是一整套 Harness 工程：memory、工具调用、MCP、multi-agent 编排。

更长期的想象空间是产品形态本身——单人使用时，agent 是你的下属；但当 harness 走向团队、组织时，它会演化成什么，还没有成熟的范式。

通过实践，对 harness 怎么做得好的几个产品设计判断：

产品设计判断
01减少暂停点
"每次都问反而比手动累"
  • 风险分级自治：低风险动作自动做、高风险才问
  • 偏好沉淀：用户做过的决策模式记下来，同类场景直接套用
  • 反向问询：先给一版让用户吐槽，比让用户描述需求容易
02上下文不污染
"长对话会让 agent 越走越偏"
  • 沙箱化任务：每个任务在独立上下文里跑，历史不互相干扰
  • 自然的产品交互结构隔离：如用 Discord 的 channel 这种产品设计
  • 文件系统作共享内存：人和 agent 都能读写的笔记，比向量数据库更透明可控
03错误不累积
"修补型 agent 越改越乱"
  • 果断回滚不打补丁：LLM 不擅长局部修改，整段重来比逐处修补更经济
  • 多 Agent 分层：执行 + 价值判断分开，让错误在层间被发现
三件事的共同方向是减少人介入的频率，但保留人对关键决策的最终判断。
05 体验 · PMF

制造 Aha Moment

AI 降低了应用制造的技术成本，也会抬高用户对传统互联网产品体验的平均预期。效率提升会越来越容易被复制，AI 应用想靠“更快解决问题”留下用户反而会更难。除了在通用场景中提高解决方案效率，产品设计本身还要从个性化视角提高体验感，创造用户愿意记住的 Aha Moment。

Aha Moment 的三种来源
01
符合直觉的交互
如 GPT 语音助手中，查询等待时打字机键盘的敲击声。
02
轻松带入已有环境
如 coding 展示工具自部署一个局域网内的投屏功能。
03
轻微超出预期的用户理解
如图片、视频、网页生成时呈现出的视觉效果。
