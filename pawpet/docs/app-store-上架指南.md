## 5. 审核重点与对策

### 5.1 IAP：必须使用苹果内购（Guideline 3.1.1）

- 生成次数、订阅全部走 StoreKit 内购，**App 内不得出现**：微信/支付宝支付、跳转 H5 付费页、客服引导转账、兑换码售卖暗示等。
- App 内、客服话术、抖音落地承接话术中都不要出现「加微信便宜充值」之类引导——审核员会搜索 App 内文本，上线后被举报同样会下架。
- 消耗型商品（生成次数）要做好 **transaction 完成确认后再发放次数、finishTransaction 前持久化** 的逻辑，避免掉单引发差评和退款。
- 价格展示一律读取 StoreKit 返回的本地化价格，不要写死「¥18」（其他储值区会出错）。文案中的人民币价格仅在中国区元数据使用。

### 5.2 用户上传照片的隐私（Guideline 5.1）

这是本 App 审核第一风险点：上传照片 → 传到服务器 → 第三方 AI 模型处理。必须完整做到：

1. **隐私政策 URL（必须）**：App Store Connect 元数据中填写，App 内设置页也要有入口。内容必须写明：收集用户上传的宠物照片、用于 AI 生成、传输给第三方模型服务商（Seedream/Seedance，即火山引擎/字节系服务）、保存期限、删除方式、联系邮箱。
2. **PrivacyInfo.xcprivacy 隐私清单**：主 App 与 Widget Extension target 都要包含。声明：
   - `NSPrivacyCollectedDataTypes`：照片/视频（Photos or Videos），用途 App Functionality，是否关联用户身份按实际填写；
   - `NSPrivacyAccessedAPITypes`：如使用 UserDefaults（App Group 共享数据必用）需声明 `NSPrivacyAccessedAPICategoryUserDefaults`，理由代码 `CA92.1`；用到 File Timestamp、Disk Space 等 API 同理；
   - 使用的第三方 SDK（如抖音/巨量转化 SDK、网络库）若在苹果「需提供隐私清单的 SDK 名单」内，必须带各自的 xcprivacy 与签名。
3. **Info.plist 用途描述**：
   - `NSPhotoLibraryUsageDescription`：「需要访问相册以选择您的宠物照片，用于生成专属虚拟桌宠」；
   - 建议优先使用 `PHPickerViewController`（不触发相册权限弹窗，隐私体验最佳，审核也更省事）；如果用 PHPicker 则无需相册权限，但 Info.plist 描述留着不出错。
   - 如支持拍照上传，加 `NSCameraUsageDescription`。
4. **App Privacy「数据收集」问卷（App Store Connect）**：如实勾选「照片或视频」「标识符（如有设备 ID/转化归因）」「使用数据（如接抖音转化 SDK）」。**接了巨量引擎转化 SDK 就必然有设备标识符收集，问卷漏报会被拒或事后下架**。如使用 IDFA 归因还需接 ATT 弹窗（`NSUserTrackingUsageDescription`）。
5. **账号与删除**：如有账号体系，必须提供 App 内删除账号入口（Guideline 5.1.1(v)）；同时提供「删除我的照片与生成内容」功能或客服通道。
6. **中国《个人信息保护法》**：首次启动弹隐私政策同意弹窗（中国区 App 实质标配）；上传他人照片的责任提示写进用户协议。

### 5.3 AI 生成内容合规（Guideline 1.2 / 中国监管）

1. **生成内容标识**：依据中国《人工智能生成合成内容标识办法》（2025-09-01 起施行），AI 生成的图片/视频需带标识。落地做法：
   - 生成的角色设定图与导出/分享的视频上加显式标识（如角落「AI 生成」水印，分享场景必须有）；
   - 文件元数据中写入隐式标识（办法要求的 metadata 标识）；
   - App 内生成结果页标注「本形象由 AI 生成」。
2. **内容审核机制**（苹果对含 AIGC 的 App 会问询，审核备注里主动说明）：
   - 上传侧：接入图片审核 API（如阿里云/火山内容安全），拦截人脸为主体的照片（避免真人肖像生成风险）、色情暴力违规图；
   - 生成侧：生成结果过一遍机器审核再返回给用户；
   - 用户侧：提供「举报/反馈」入口 + 客服邮箱，承诺 24 小时内处理（苹果对 UGC 的标准三件套：过滤、举报、拉黑/处理，能做尽量做全）。
3. **审核备注（App Review Notes）主动声明**：说明 AI 生成仅针对宠物照片、有前置人脸拦截、生成内容有标识与审核，可显著降低问询轮次。
4. **生成式 AI 服务备案（中国）**：面向公众提供生成能力理论上涉及网信办深度合成/生成式 AI 备案。当前调用的是火山引擎已备案模型（Seedream/Seedance），建议在隐私政策中披露技术服务提供方；如后续被要求自行备案再推进，初期以「使用已备案第三方模型服务」口径应对。

### 5.4 ICP 备案：中国区上架的现实问题

**现状**：2023 年起，App Store 中国区新上架 App 必须在 App Store Connect 中填写 **ICP 备案号**（App 备案，不只是域名备案），否则无法在中国大陆区发布。

**备案流程与周期**：
1. 前置条件：企业主体（个人主体可备但类目受限，含支付/AIGC 的 App 实务上强烈建议企业主体）+ 国内服务器/云服务商（阿里云/腾讯云/火山引擎均可代提交）。
2. 流程：域名备案（若未备）→ 通过云服务商提交 **App 备案**（填 App 名称、平台 iOS、Bundle ID `com.kotoko.pawpet`、公钥/MD5 等）→ 省通信管理局审核。
3. 周期：材料齐全的情况下通常 **1-4 周**；加上域名备案串行办理，整体预留 **3-6 周**。
4. 注意：备案的 App 名称要与上架名称一致（「爪爪桌宠」），后改名需变更备案。

**无备案时的两个方案与利弊**：

| 方案 | 做法 | 优点 | 缺点/风险 |
|------|------|------|-----------|
| A. 先上其他区域 | 首发香港/台湾/美国区等无需 ICP 的区域，中国区待备案完成后追加 | 不阻塞上线节奏；可先跑通审核、IAP、生成管线全链路；积累版本与评分 | 与「主投抖音」严重冲突——抖音用户基本是大陆 Apple ID，无法在非中国区商店下载，**投放链路断裂**；价格需配置港币/美元 |
| B. 挂靠已有备案主体 | 用已完成 ICP 备案的公司主体开发者账号上架，或借用其备案 | 最快进中国区 | 合规风险高：备案主体与实际运营方不一致，被核查可注销备案连带下架；开发者账号归属、收入分成、App 迁移都受制于人；**不建议长期方案** |

**结论建议**：抖音投放是核心增长路径 → **中国区是必选项，备案是硬前提**。正确排期：立刻启动企业主体 + 域名 + App 备案（与开发收尾并行），期间可先用 TestFlight 内测打磨；如想提前验证审核，可先提交香港区（方案 A）但不要在抖音投放前指望它承接流量。

### 5.5 订阅合规（Guideline 3.1.2）

订阅页（Paywall）必须包含，缺一项都可能被拒：
- [ ] 订阅名称、时长、价格（来自 StoreKit 本地化价格）；
- [ ] 自动续期说明（扣款时间、取消方式）；
- [ ] **「恢复购买」按钮**（消耗型不需要恢复，但订阅必须有；恢复逻辑用 `AppStore.sync()`/`restoreCompletedTransactions`）；
- [ ] **隐私政策链接 + 用户协议（EULA）链接**，可点击打开；
- [ ] 关闭按钮清晰可见，不得强制订阅才能进入 App（示例宠物免费体验就是合规缓冲）。
- 元数据层面：App 描述中也要含订阅价格与条款说明（1.5 节描述已包含）。
- 「每月 2 次生成额度」要写清是否可累积、过期规则，避免消费争议与差评。

### 5.6 「每日前 5 名免费」的合规表述

风险：表述含糊会被审核或用户理解为抽奖（Sweepstakes/Contest，触发 Guideline 5.3 与分级问卷「竞赛」项），也可能涉中国《反不正当竞争法》有奖销售信息披露义务。

对策——把它定义成**先到先得的限量免费权益**，而非抽奖：
1. App 内有明确规则页（从活动入口一键可达）：
   - 每日 00:00（北京时间）重置名额，共 5 个；
   - 判定标准：当日前 5 位**完成照片上传并点击生成**的用户（写清触发动作，避免「前 5 名」歧义）；
   - 每个 Apple ID/设备限领 1 次（写明频次）；
   - 名额用完后页面实时显示「今日名额已抢完，明天 00:00 再来」；
   - 活动解释权条款 + 有效期（写「长期有效，调整将提前公告」）。
2. 不使用「中奖」「抽取」「幸运」类词汇，统一用「免费名额」「先到先得」。
3. 分级问卷「竞赛」勾选「无」，审核备注中主动一句话说明：「每日免费名额为先到先得的限免权益，非抽奖，无随机性，规则见 App 内 XX 页」。

### 6.3 App Store Connect 配置

- [ ] 新建 App：名称「爪爪桌宠-AI宠物桌面小组件」、主语言简体中文、Bundle ID 选 `com.kotoko.pawpet`、SKU 自定（如 `pawpet001`）；

- [ ] 如生成功能需要登录或有服务端开关，提供 Demo 账号。

### 6.4 内购商品配置步骤（App Store Connect → 我的 App → 内购/订阅）

**消耗型（生成次数）**：
1. 「App 内购买项目」→ 创建 → 类型选 **消耗型（Consumable）**；
2. 产品 ID：`paw.generate.once`（注意：产品 ID 一经创建不可改、删除后 ID 永久占用，确认再建）；
3. 参考价格：选中国区 ¥18 对应档位；
4. 本地化（简体中文）：显示名「专属桌宠生成 1 次」，描述「上传照片，AI 生成一只专属虚拟桌宠（含设定图+8 个动作）」；
5. 上传审核截图（购买页截图）+ 审核备注；状态变为「准备提交」后，**与 App 首版二进制一起勾选提交**（首批 IAP 必须随版本送审）。

**自动续期订阅（Pro）**：
1. 「订阅」→ 创建订阅群组（如 `PawPet Pro`，群组本地化名「爪爪 Pro 会员」）；
2. 群组内创建两个商品：
   - `paw.pro.monthly`，时长 1 个月，¥12 档位；显示名「爪爪 Pro 月度会员」；
   - `paw.pro.yearly`，时长 1 年，¥68 档位；显示名「爪爪 Pro 年度会员」，同组内苹果自动支持互相升降级；
3. 本地化描述写清权益：「每月 2 次专属生成额度 + 解锁全部组件样式 + 多宠轮播」；
4. 每个订阅商品上传审核截图；
5. 可选：配置「推介促销/优惠」（如年订阅首年优惠）留作后续运营弹药；
6. App 内购买页实现 5.5 节全部合规元素。

**服务端**：
- [ ] App Store Server Notifications V2 回调地址配置（订阅状态变更、退款监听——消耗型退款要扣回未用次数）；
- [ ] 生成沙盒测试账号（用户与访问 → 沙盒技术），真机走完：购买消耗型 → 发次数；订阅 → 升级/降级/取消 → 恢复购买 全链路。
